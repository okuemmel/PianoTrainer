# Sprachen erweitern

Die Weboberfläche lädt ihre Kataloge aus `data/i18n/`. Die Sprache wird pro Browser in `localStorage` gespeichert; der Standard ist Deutsch. Firmware und API verwenden weiterhin dieselben technischen Kennungen. Die API liefert deutsche Ausgangstexte, die Oberfläche übersetzt sie bei der Anzeige.

## Weitere Sprache hinzufügen

1. `data/i18n/de.json` nach beispielsweise `data/i18n/fr.json` kopieren.
2. `language` auf `fr` setzen und die Werte unter `messages` übersetzen. Die Schlüssel bleiben unverändert. Sie sind nach dem gettext-Prinzip überwiegend die deutschen Ausgangstexte; `score.rest` unterscheidet eine musikalische Pause vom Playerknopf.
3. In `data/i18n/languages.json` `{"code":"fr","name":"Français"}` ergänzen. Sprachcodes bestehen aus zwei Kleinbuchstaben, optional gefolgt von einem Regionscode wie `en-GB`. Der Name erscheint in der eigenen Sprache.
4. `npm test` und `npm run format:check` ausführen, LittleFS neu bauen und hochladen. Die Firmware erlaubt vorhandene JSON-Kataloge unter `/i18n/`, ohne für jede Sprache eine neue Route zu benötigen.

Fehlende Einträge fallen auf Deutsch zurück. Manche Meldungen sind aus Fragmenten zusammengesetzt; Leerzeichen am Rand bleiben erhalten. Übersetzte Fragmente können bei Bedarf zusätzliche Leerzeichen enthalten, etwa vor ` search results`. Die Liste `prefixes` übersetzt dynamische Meldungen, deren unveränderter numerischer Rest angehängt wird. Die englische Datei zeigt Beispiele. Technische IDs, MIDI-Notennummern und Bestätigungswörter wie `WERKSRESET` sind keine Übersetzungsschlüssel für ausgehende API-Befehle.

## Neue Oberflächentexte

Statische HTML-Textknoten sowie `title`, `aria-label` und `placeholder` werden beim Start mit ihrem Ausgangstext verbunden. Den normalisierten Text als Schlüssel in beiden Katalogen eintragen. Dynamische Texte mit `I18n.text(element, () => I18n.t("Ausgangstext"))` setzen; einzelne Bestandteile einer Meldung können separat übersetzt werden. `I18n.attr(element, "aria-label", () => ...)` aktualisiert Attribute. Dateinamen, SSIDs und andere Nutzereingaben als unveränderte Werte einsetzen.

Die Bindungen gehören zu einzelnen Textknoten und werden über eine WeakMap gehalten. So überlebt ein Eingabefeld innerhalb eines Labels die Sprachumschaltung, und entfernte Statuszeilen werden nicht dauerhaft festgehalten. Der Sprachwechsel aktualisiert nur die Anzeige und zeichnet die Notenvorschau neu; er startet keine MIDI-, Trainings- oder Playerbefehle.

Die Kataloge werden nach Bedarf lokal geladen und für die laufende Sitzung zwischengespeichert. Bei einem Ladefehler bleibt die bisherige Sprache aktiv und die Auswahl kann erneut versucht werden. Fehler beim ersten Laden werden oberhalb der Seite angezeigt. Für die Erweiterung stehen Prüfungen für Katalogabdeckung, Fallback, neue Sprache, Ladefehler, konkurrierende Sprachwahl und laufende Übung/Wiedergabe zur Verfügung. Eine visuelle Prüfung der neuen Übersetzung auf Handy und Tablet bleibt sinnvoll.

PlatformIO erzeugt über `tools/platformio_assets.py` automatisch deterministische `.json.gz`-Begleitdateien. Sie sind generiert und werden nicht eingecheckt. Browser mit Gzip-Unterstützung erhalten die komprimierte Datei mit `Content-Encoding: gzip` und `Vary: Accept-Encoding`; andere Clients erhalten das originale JSON. JSON-Dateien direkt bearbeiten, nicht die Archive. Der Kompressor lässt sich auch mit `python3 tools/compress_languages.py` aufrufen. Die zusätzlichen Dateien werden zusammen mit den Originalen nach LittleFS übernommen.
